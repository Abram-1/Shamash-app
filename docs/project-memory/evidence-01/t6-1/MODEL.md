# Модель событий и финансовых ссылок

| Слой | Ответственность |
|---|---|
| `synthetic.js` и `construction-fixtures.js` | Исходные синтетические объекты и события. Карта наследует идентификаторы из инвентаризации. Полный путь из сегментов является постоянным ID объекта; название используется только как подпись. Для записи уровней проекта или здания путь заканчивается на соответствующем уровне. |
| `history-model.js` | Валидирует реестр и непрерывный префикс области. Проверяет даты, источник, ID, версию, статус, автора/источник и метаданные. Неоднозначный реестр останавливает экран. Некорректные события и повтор того же ID варианта исключаются с диагностикой. |
| `screen.js` | На уровне проекта или здания показывает собственные и дочерние события. В истории квартиры отдельный блок содержит события компании, проекта, здания и этажа на её точной ветви. Карточка связанного события показывает исходную область. |
| `finance-reference.js` | Читает закрытую схему ссылки. Поля включают договор, акт и его версию, источник объёма и версию приёмки, объём и единицу, брутто, удержание, дельту и итог в агорах. |

Ключ записи состоит из полной области, источника, исходного ID, версии и явного варианта. Обычная классификация бесконфликтных цепочек сохранена. Для утверждения после конфликта нужны точный ID кандидата, полный список разрешённых конфликтных версий, синтетический статус APPROVED_SYNTHETIC и ссылка на единственную действующую запись «Решение» по источнику, ID, версии и области. Решение должно иметь синтетическую роль SYNTHETIC_VERSION_REVIEW, находиться в той же ветви на уровне проекта или ниже и не требовать собственного разрешения конфликта. Одно отдельное свидетельство связывает решение и кандидата по направлению, типу и точному варианту. Некорректное утверждение диагностируется. При двух вариантах головы утверждение одного варианта не устраняет конфликт. После действительного утверждения предыдущие варианты остаются в архиве. Это локальная синтетическая проверка; поле роли не удостоверяет реального издателя.

Связь содержит тип, направление и два точных конца. Межуровневая связь требует общей компании и проекта и совместимой ветви. Свидетельство должно совпадать по обоим концам и типу. Архивная, конфликтная, ожидающая утверждения или отсутствующая версия не даёт действующего подтверждения, включая связь приёмки с работой.

Согласованность финансовой ссылки проверяется по связанным версиям договора и приёмки, совпадению нормализованного объёма и единицы, вычитанию предоставленного удержания из предоставленной суммы до удержания и разности с предшествующим снимком того же акта. Проверяются явные свидетельства обеих связей и сохранение идентичности между версиями. Никакие ставки, начисления или удержания не рассчитываются заново. Несогласованная ссылка исключается с диагностикой.

Синтетические данные моделируют CM01/CM02/CM09/CM14/CM24/CM25/CM28. Действующие модули не подключены. Для финансовой ссылки пример v1 показывает 80 м², удержание 320 ₪ и расчёт 6 080 ₪; v2 — 75 м², удержание 300 ₪, корректировку −380 ₪ и итог 5 700 ₪. Это демонстрационные суммы, без разрешения оплаты, правовой приёмки и записи в финансовый журнал. CM04/CM17 и R02 не используются.

Восстановление означает повторное формирование той же проекции из неизменных локальных фикстур. Записи в localStorage, перенос рабочих данных и многопользовательский режим отсутствуют. Фото представлены синтетическими метаданными. Заявление, выполненная работа и подтверждение в фикстуре — отдельные типы событий.

Для утверждения сравниваются существующие даты документов: решение датировано не ранее версии. Источник дат регистрации не используется. Только точный evidenceId проверенного утверждения даёт подтверждение соответствующей связи.
